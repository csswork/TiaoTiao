# TiaoTiao：样本采集、AI 识别、规则沉淀与分享方案

更新日期：2026-11-01。

**0.3.0 修订：通用自动学习现适用于所有已选应用。Jev 在初期检查布局和小型关闭控件，端侧 OCR 与视觉模型并行补充；后台缓存晚到结果、原生控件优先、独立 AI 与时序验证后启用。下文逐条人工确认仅描述旧普通兼容路径；当前实现、接入服务能力与限制以 README 的“通用自动学习”为准。**

实施状态：首版 0.1.0 已实现节点识别、Jev 官方接口、试跳与人工确认、JSON 规则复用及导入导出、系统分享、手动 HTTPS/WebDAV 同步和基础本地样本管理。截图识别、持续上传队列与链接分享仍为后续阶段。安装及当前边界见 [README](../README.md)，本文件其余内容描述完整设计。

适用场景：个人自用 Android 开屏广告跳过工具，直接安装 APK。数据范围是开屏广告界面样本与跳过规则。方案以减少逐应用适配、标注和维护为目标。

## 1. 总体选择

优先验证 Jev 作为唯一 AI 后端。第一版不要求同时接入 DeepSeek 或 OpenAI，也不从零训练模型。Android 负责观察和执行，Jev 负责结构化识别、分类和目标选择，程序根据选择结果生成规则。

最终确认的工作方式：未知界面由 Jev 判断并生成候选方案，经人工确认实际跳过结果后，才将规则标记为已验证并保存为 JSON。再次遇到匹配界面时，直接使用已验证规则，无需调用 Jev 或再次人工确认。

“遇到过”以应用和广告界面结构、目标按钮特征为依据。广告图片或文案更新，只要规则条件仍满足，就可以复用；已验证规则失配、失效或应用版本超出适用范围时，重新进入未知界面的判断与确认流程。

这是基于官方能力的设计方案，尚未调用真实模型或在手机上测试。是否达到日常使用要求，需要通过中文开屏广告、正常页面和实际网络条件验证。

| 工作 | 实现方式 | 当前边界 |
| --- | --- | --- |
| 从界面节点中选择跳过目标 | 将候选节点及页面特征交给 Jev 的 Choice / Noul 问题 | 需要 Android 提供真实候选节点和明确的问题 |
| 从图片识别广告与按钮 | Jev 图片输入；必要时使用 Box 定位 | 官方标为实验功能，作为独立验证分支 |
| 自动分类样本 | Jev 在预先定义的类别中选择 | 允许“不确定”，不强制归类 |
| 自动生成跳过规则 | 本地规则编译器把选中节点、页面约束组装成声明式规则 | 无需模型编写任意代码或脚本 |
| 执行点击与确认结果 | Android 无障碍服务与本地状态机 | 每次执行前重新确认页面和目标 |
| 上传、同步和分享 | 普通 Android 网络任务及私有数据服务 | 不依赖模型完成文件传输 |

Jev 的 Choice 支持固定选项和概率输出；图片输入与 Box 是另行开启的实验能力。结构化输出并不保证语义判断正确，阈值需要用本项目的数据校验。

## 2. 整体流程

```text
进入已启用的应用 → 建立短时检测会话 → 读取当前界面
    ├─ 已验证规则命中 → 重新定位目标 → 点击 → 观察结果
    └─ 未命中
         ├─ 有足够的可读节点 → Jev 选择候选节点 / 等待 / 不处理
         └─ 节点不足且已开启图片分析 → Jev 识别图片 / 实验性 Box 定位
                    ↓
         本地校验：应用、页面、目标、时效、动作范围
                    ↓
         生成待确认规则 → 试跳 → 人工确认实际结果，或放弃
                    ↓
         确认通过后标记已验证 → 保存 JSON；自动整理与归类样本
                    ↓
         本地复用；按设置上传私有库；按选择导出分享包
```

常见且已验证的页面使用本地规则。新页面才请求 Jev；单次会话限制请求次数和总耗时。先测 Jev 单独的效果，只有实际失败样本证明需要时，再通过统一接口加入其他模型。

## 3. Android 采集与执行

基础能力沿用 Kotlin、Compose 和 AccessibilityService。可保留 Android 8 / API 26 起的节点识别路径；无障碍截图接口从 Android 11 / API 30 起提供，完整图片路径按能力开启。低版本先支持节点采集及手动导入图片，实时截图方案单独评估。

自动采样限定在你选中的应用和短时检测会话内。每次启动会话设置超时，不因普通页面内容更新不断延期。采样与自动跳过分别设开关，便于只观察、不执行。

保留两种入口：

- 自动采样：未匹配已验证规则、检测到新界面结构或处理失败时，限量保存样本。
- 主动采样：选择“采集该应用下一次开屏”，打开目标应用，采集结束后回到样本列表。

优先保存必要节点属性。截图先在内存分析，默认只持久化经过处理的相关区域；不持续录屏。遇到受保护页面或截图失败，记录“图片不可用”，继续使用节点能力或结束本次检测。

执行范围限制为跳过目标点击、有限等待和结束检测。第一版不向模型开放文字输入、购买、安装、授权确认、任意应用启动或任意脚本能力。

请求返回后重新读取当前窗口。候选 ID 仅在该次观察中有效，程序必须重新找到对应目标；应用切换、页面变化、方向变化或结果过期时，丢弃旧决策。图片坐标需要映射回真实窗口，并重新验证目标区域，不能直接复用到另一帧或另一台手机。

## 4. Jev 单模型设计

节点路径一次请求回答几类问题，减少多轮交互：

| 问题 | 输出范围 |
| --- | --- |
| 页面属于哪类 | 可跳过开屏、等待中的开屏、普通页面、引导/登录、系统弹窗、不确定 |
| 当前是否有符合条件的跳过目标 | 是/否及相关概率 |
| 目标是哪一个 | 仅从实际观察到的候选 ID 中选择，并提供无合适目标的出口 |
| 当前应采取什么动作 | 点击候选、短暂等待、结束本轮 |

页面文本、广告文案和截图都作为待分析数据，不能覆盖程序的动作限制。Jev 输出必须通过本地格式、候选集合和上下文校验。

当节点不可读时，可以把脱敏后的截图或相关区域提供给支持图片的 Jev 型号，结合 Box 返回的位置进行实验。图片分支的验证结果独立统计，不能因为文本路径表现好就默认图片定位可靠。

规则编译采用固定模板：目标节点 ID/资源 ID、有限文字条件、父子关系、页面广告特征、适用包名与版本。Jev 提供判断，程序选择模板并填充已观察到的属性。禁止生成或导入任意执行代码。

## 5. 数据结构与自动归类

将样本、规则、运行结果分别保存，避免把一次模型判断直接当作已验证规则。

| 数据 | 主要字段 |
| --- | --- |
| Sample | 随机 sampleId、采集会话 ID、包名、应用版本、系统 API、语言、方向、窗口尺寸、经过筛选的节点树、可选局部图片 |
| Annotation | 样本类别、目标候选 ID/图片区域、判断来源、模型版本、提示版本、概率、是否经人工或独立测试确认 |
| Rule | ruleId、revision、包名、已验证版本范围、页面条件、目标条件、动作、来源样本 ID、状态 |
| RunResult | 规则/模型版本、命中方式、动作是否被系统接受、观察到的结果、耗时、失败原因 |

JSON 文件作为规则同步与分享的标准载体，建议按包名保存，例如 `rules/com.example.app.json`，文件内可包含多个界面变体的规则。包含 schemaVersion、ruleId、revision、匹配条件、动作、适用范围，以及人工确认的验证状态和时间。本地数据库可以建立检索索引，导入导出均以 JSON 规则格式为准。

组织方式为“应用 → 应用版本 → 界面类型 → 样本与规则”。自动标签包括文字按钮、图片按钮、倒计时、节点不可读、无法确认目标等。

去重使用规范化节点结构和经过筛选的静态特征，忽略倒计时等动态值；图片相似性只用于提示可能重复，不能单凭相似图片合并规则。保留正常首页、登录页、引导页等反例，防止把所有“跳过”都当作广告。

保存前过滤输入框、密码、键盘以及与跳过无关的正文。文本和 contentDescription 使用允许字段/允许内容策略；图片采用裁剪与遮挡。自动脱敏不能证明不存在敏感信息，无法按策略处理的样本留在本地待处理，不自动上传。

## 6. 自动检查与人工确认

规则流转：草稿 → 自动检查通过 → 试跳 → 人工确认实际结果 → 已验证；发现误触或条件失效后转为停用并重新识别。普通运行日志与训练/验证标签分开。待确认规则不进入日常自动跳过路径。

自动验证检查以下内容：

- 目标在采集样本中真实存在；规则不能匹配候选集合之外的控件。
- 在对应正例上能定位目标，在正常页面反例上不应触发。
- 样本按应用版本、会话和页面变体划分验证集，去重后评估，避免重复图片夸大效果。
- 真实点击后观察广告特征和已知页面状态的变化；仅有点击返回 true 或控件消失时，结果可以是“未知”。

模型给出的标签不能独自证明规则正确。初期需要一小批独立确认的基准样本；使用过程中，人工确认每条新规则的实际效果，并处理冲突、无法判断和误触反馈。规则提取、字段填写、样本归类和文件保存自动完成，不要求手写规则。

人工确认是新规则进入已验证状态的必要条件，自动检查或模型高置信度不能跳过该步骤。已确认规则在匹配条件满足时直接执行；扩大应用/版本适用范围、改变匹配条件或动作等行为性更新，需要重新验证与确认。

一键反馈支持“有效”“没跳过”“点错了”。点错反馈立即停用对应规则，并保留可回滚的上一版本。

## 7. 上传与私有存储

提供三个独立设置：本地采样、Jev 云端分析、私有库同步。启用云端分析会把选定数据发送到 TypeSafe；私有库同步决定是否持久化备份，二者独立控制。明确说明首次允许的应用、字段与图片范围，之后在此范围内自动处理，减少逐次确认。

个人版采用一个轻量私有 HTTP 服务、SQLite 元数据和私有文件目录即可。服务同时承担 Jev 请求转发、样本/规则存储、分享包下载；后续有需要再替换文件存储。无需先开发公共社区或多用户注册系统。

正式使用时 Jev 密钥放在私有服务端，手机持有设备访问凭据。技术验证阶段可采用运行时输入密钥并用系统密钥能力保护，不能把密钥编译进 APK 或放入分享包。

上传流程为“准备经过处理的不可变数据包 → 排队 → 上传 → 服务端校验 → 返回回执”。Android 使用 WorkManager 处理持久上传任务、网络约束和退避重试；按包 ID 和摘要实现幂等。

取消自动同步或删除待上传样本时，同时取消对应队列。上传失败保留本地副本；模型请求失败、超时或返回旧决策时结束本轮，不在后台重放点击。

首版接口范围：设备鉴权、样本包上传/查询/删除、规则版本上传/下载、分享链接创建/撤销。文件大小、格式和权限均在服务端校验，服务使用 HTTPS。

## 8. 分享与导入

默认分享经过验证的规则。样本和图片作为单独的诊断包，由你选择是否附带。

离线包建议使用 `.tiaotiao.zip`：

```text
manifest.json      # 格式版本、包 ID、文件清单和摘要
rules.json         # 声明式规则及各自版本
samples/           # 可选，经过处理的样本
previews/          # 可选，局部图片
```

通过 Android 系统分享面板交给你选择的应用；这只是导出能力，方案阶段不代你向任何人发送文件。

需要链接分享时，由私有服务生成限定数据包、带有效期且可撤销的只读链接。撤销后阻止后续下载，已经下载的副本无法远程收回。

导入前检查格式版本、文件数量/大小、路径、摘要、包名、规则动作以及版本适用范围。摘要用于发现损坏，不代表发布者可信。陌生来源规则先禁用；可信来源更新也不能覆盖本地明确停用的规则。

## 9. 实施顺序与验收

| 阶段 | 交付内容 | 验证重点 |
| --- | --- | --- |
| A：单模型验证 | Android 节点采集、Jev 分类/选择、只观察模式 | 中文标签识别、普通页面拒绝处理、响应耗时 |
| B：自动跳过 | 受限点击、页面重校验、结果观察、本地缓存规则 | 冷/热启动、倒计时变化、切换应用、旧决策丢弃 |
| C：图片实验 | 截图能力检查、Jev 图片输入/Box、图片样本 | 小字、图片按钮、坐标映射、节点不可读场景 |
| D：数据管理 | 自动采样、归类去重、规则编译、回放、反馈停用 | 反例误匹配、规则版本、人工处理次数 |
| E：上传分享 | 私有服务、上传队列、离线导出、链接分享与导入 | 断网重试、幂等、取消上传、撤销链接、导入校验 |

每阶段记录：误触数量、可确认跳过比例、未知结果比例、放弃处理比例、P50/P95 总耗时、调用次数、实际费用、耗电，以及每批新页面需要人工介入的次数。指标覆盖网络传输和 Android 执行，不能只采用模型服务端推理时间。

第一轮选择少量常用应用和正常页面反例，分别测试节点与图片路径。样本集“未发生误触”只代表该测试范围，不推断所有应用都安全。若 Jev 已满足要求，维持单后端；若某类样本持续失败，再评估备用识别器。

## 10. 选型依据与后续扩展

根据目前官方文档，Jev 已提供本方案需要的结构化选择与图片实验能力，因此先验证单模型路线是合理的工程选择；这不等于已证明其在开屏广告上的速度或准确率优于其他模型。

DeepSeek 官方当前提供支持图片输入的 `deepseek-flash`。OpenAI API 提供图像分析和结构化输出。未来如确需混用，可以让其他视觉模型提取候选、Jev 做选择；也可以替换整个识别后端。统一内部接口即可，不把多模型串行调用设为每次启动的必经路径。

模型接口建议围绕 Observe、Classify、SelectTarget 和 LocateInImage 划分能力；识别结果最终都映射为本地候选目标或明确的不处理结果。新增后端不应扩大 Android 的动作权限。

社区项目 `dougsong/jev-android` 可以参考其节点观察、候选动作和新鲜度校验设计。其 README 明确表示 API 尚不稳定，且该版本不支持截图视觉和无人值守长期后台任务，不能直接视为本项目完整实现。
